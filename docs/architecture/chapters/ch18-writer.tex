\section{Pipeline shape}

\begin{verbatim}
LogSource -> raw_channel -> ParserTask -> parsed_channel -> GraphWriter -> Graph
\end{verbatim}

Both channels are bounded \code{tokio::sync::mpsc} queues (default
capacities 4 and 8 respectively, configurable per source). A full
channel backpressures the upstream stage; a source whose poll
cannot find room in \code{raw\_channel} blocks on
\code{send().await} until the writer has drained enough to make
progress.

    \item \filepath{graph\_hunter\_core/src/ingest/overflow.rs} ---
        serialises queued \code{ParsedBatch}es to disk on

\section{Lock contention}

The writer holds \code{graph.write()} for the duration of a single
\code{insert\_triples\_chunk} call and releases between batches.
Readers (hunts, analytics queries, enrichment queries) acquire
\code{graph.read()} and coexist with each other. Typical batch
sizes are 1--5 K triples, so a write hold lasts milliseconds ---
readers backing off once per batch is cheap.

\begin{invariant}[Writer uniqueness]
Each session has at most one \code{GraphWriter} task active at any
time. The \code{SessionStore} registers the writer's
\code{JoinHandle} when the task starts and refuses to start a
second; this rules out writer-writer races entirely.
\end{invariant}
