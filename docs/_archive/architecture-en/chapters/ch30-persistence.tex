\section{On-disk layout}

\begin{itemize}
    \item Windows: \code{\%APPDATA\%\textbackslash GraphHunter\textbackslash sessions\textbackslash <id>.json}
    \item Unix: \code{\$HOME/.local/share/GraphHunter/sessions/<id>.json}
\end{itemize}

\code{<id>} is validated against \code{[A-Za-z0-9\_-]\{1,128\}} to
prevent path traversal. The path is constructed via
\code{PathBuf::join}, never string concatenation.

\section{SessionFile shape}

\begin{lstlisting}[style=rust]
pub struct SessionFile {
    pub id:              String,
    pub name:            String,
    pub created_at:      i64,
    pub entities:        Vec<Entity>,
    pub relations:       Vec<Relation>,
    pub path_node_ids:   Vec<String>,
    pub notes:           Vec<Note>,
    pub datasets:        Vec<DatasetInfo>,
    pub tags:            Vec<EntityTag>,
    // NO ai_conversation -- chat is deliberately ephemeral.
}
\end{lstlisting}

\section{Load progress}

Loading is async. The \code{EventEmitter} receives
\code{SESSION\_LOAD\_PROGRESS} events at each stage: parsing the
file, inserting entities, inserting relations, rebuilding indexes
(scorer finalize), done. The UI renders a progress bar; HTTP / MCP
simply ignore the events (\code{NoopEmitter}).

\section{v2 migration (deferred)}

When the P3 MVCC writer change lands, legacy edges (loaded from
v1 files) must be backfilled with a synthetic \code{ingested\_at}.
The plan is to use the edge's \code{timestamp} as the backfill
value: it's not exactly right (the edge was ingested at some later
moment), but it's a defined, deterministic choice that lets v2
snapshot queries produce sensible results against v1 data. The UI
gets a ``approximate snapshot'' banner so the analyst knows.
