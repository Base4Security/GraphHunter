\section{Reclasificación de contribuciones}

La v1 del paper listaba el GNN como contribución \emph{validada
empíricamente}. Tras el ciclo 2026-04 esto se rebalanceó:

\begin{itemize}
    \item \textbf{Contribución \emph{arquitectónica} (mantenida)}:
    ADR-003 describe un gate opcional con criterio de admisión
    explícito; GraphHunter queda listo para absorber modelos
    entrenados sin re-diseñar el scoring.
    \item \textbf{Contribución \emph{empírica} (retirada)}: no se
    reclama mejora cuantitativa end-to-end atribuible al GNN mientras
    no exista un modelo entrenado contra datasets de las tres
    familias de logs que GraphHunter cubre (Sysmon/Sentinel/Forti).
    Los números del paper provienen exclusivamente de los cuatro
    componentes con $w_5 = 0$.
\end{itemize}

\section{Roadmap 30/60/90 (desde 2026-04-24)}

\subsection*{2026-05-24 ($+$30 días)}

\begin{itemize}
    \item Cerrar las dos aristas residuales \filepath{core} $\to$
    \filepath{platform} (via crate \filepath{core/ingest-types}

\end{itemize}

\subsection*{2026-06-24 ($+$60 días)}

\begin{itemize}

    \item Spike de \code{iceberg} con CI Windows estable.
\end{itemize}

\begin{itemize}
    \item DSL v2 como stable: registries con modo

    sesión/usuario.
\end{itemize}

\section{Regla de cierre}

Una \emph{claim} sólo entra en la tabla de este capítulo cuando (a)
hay un artifact concreto y (b) ese artifact corre verde en CI. Un
reclamo pendiente de evidencia vive en \ref{sec:paper-limites}, no
aquí. La divergencia entre ambos capítulos es el síntoma que
dispara el próximo ciclo de trabajo.
