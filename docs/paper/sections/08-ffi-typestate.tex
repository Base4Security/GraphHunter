\chapter{FFI con typestate y aislamiento}
\label{sec:paper-ffi}

\section{Problema del FFI}

El motor de matching vive en C++ (\filepath{libgraphmatch}) para
acceder a intrínsecas AVX2. El resto del sistema es Rust. El
cruce Rust$\leftrightarrow$C++ es notorio por tres clases de bugs:

\begin{enumerate}
    \item \textbf{Uso en estado inválido}. Llamar \code{gm\_match}
    sobre un grafo que todavía acepta inserciones, o \code{gm\_add\_node}
    sobre uno finalizado.
    \item \textbf{Leaks}. Olvidar \code{gm\_graph\_free},
    \code{gm\_results\_free}.
    \item \textbf{ABI skew}. Actualizar la \code{.dll}/\code{.so}
    sin recompilar Rust y correr con struct layouts desalineados.
\end{enumerate}

El patrón de diseño responde a cada uno con una herramienta del
sistema de tipos de Rust.

\section{Typestate para estados inválidos}

\emph{Typestate} codifica el estado del objeto como parámetro de
tipo:

\begin{lstlisting}[language=Rust]
pub struct GmGraph<State> {
    handle: NonNull<gm_graph>,
    _state: PhantomData<State>,
}

pub struct Building;
pub struct Finalized;

impl GmGraph<Building> {
    pub fn add_node(&mut self, id: u32, ty: u8) -> Result<()> { ... }
    pub fn add_edge(&mut self, ...) -> Result<()> { ... }
    pub fn finalize(self) -> Result<GmGraph<Finalized>> { ... }
}

impl GmGraph<Finalized> {
    pub fn matcher<'g>(&'g self) -> Result<GmMatcher<'g>> { ... }
}
\end{lstlisting}

\code{add\_node} no existe sobre \code{GmGraph<Finalized>};
\code{matcher} no existe sobre \code{GmGraph<Building>}. El mal uso
es un error de compilación, no un \emph{panic} en runtime ni
\emph{undefined behavior} en el binario C++.

\section{RAII para recursos}

Cada wrapper Rust implementa \code{Drop} que llama a su destructor
C correspondiente:

\begin{lstlisting}[language=Rust]
impl<State> Drop for GmGraph<State> {
    fn drop(&mut self) {
        unsafe { gm_graph_free(self.handle.as_ptr()) }
    }
}
\end{lstlisting}

Las instancias de \code{GmResults} y \code{GmMatcher} siguen la
misma disciplina. El \code{'g} en \code{GmMatcher<'g>} captura el
lifetime del grafo, previniendo \emph{use-after-free} vía
borrow-checker.

\section{Versionado de ABI}

La biblioteca expone dos símbolos metadata:

\begin{lstlisting}[basicstyle=\ttfamily\small]
uint32_t gm_abi_version(void);       /* major * 10000 + minor * 100 + patch */
const char* gm_simd_isa(void);       /* "avx2", "sse4.2", "scalar" */
\end{lstlisting}

Al cargar el FFI, Rust verifica:

\begin{lstlisting}[language=Rust]
const REQUIRED_ABI: u32 = 1_00_00;
let actual = unsafe { gm_abi_version() };
if actual / 10000 != REQUIRED_ABI / 10000 {
    panic!("ABI mismatch: got {}, need major={}", actual, REQUIRED_ABI/10000);
}
```
\end{lstlisting}

Major mismatch es \emph{panic} inmediato. Minor/patch mismatch es
warning. Esto transforma un bug silencioso en un \emph{fail-fast}
observable.

\section{Consecuencia arquitectónica}

El FFI queda encapsulado en una sola crate (\code{matcher-ffi}
dentro de \code{core/}). El resto del sistema usa un handle Rust
opaco. Los reviewers de \code{platform/*} no necesitan razonar
sobre UB, alineación o ABI. Es la materialización concreta de
\emph{shearing layers}: el dolor de C++ no \emph{supura} hacia
arriba.

La decisión se documenta en ADR-002 del libro \emph{Arquitectura}.
