\chapter{Estado de implementación}
\label{sec:estado}

Este capítulo es el \emph{cut} de lo que está implementado vs lo que
está planificado para el ciclo en curso. No es exhaustivo ---la
ADR y el código son la fuente de verdad--- pero resuelve la pregunta
operativa del lector: ``si abro \filepath{core} ahora, ¿qué voy a
encontrar funcional y qué voy a encontrar en \emph{feature flag}?''

\section{Invariantes del \emph{default build}}

Con \code{cargo build --workspace} (sin \emph{features}) se garantiza:

\begin{enumerate}
    \item Ningún símbolo de ORT ni de un modelo GNN queda linked.
    Verificable con \code{cargo tree -p graph\_hunter\_gnn --no-default-features}.
    \item Ninguna llamada de red en \emph{startup}.
    \item El \emph{scoring} compuesto es determinista: tests
    \code{scoring\_v1\_is\_bit\_for\_bit\_reproducible} y
    \code{scoring\_v1\_default\_profile\_ignores\_injected\_gnn\_scores}
    pinnean esta propiedad.
    \item \code{scripts/check-layering.sh} verifica que no existan
    aristas \filepath{core} $\to$ \filepath{platform} no-whitelisted.
    Las dos aristas legítimas están registradas en
    \filepath{docs/arquitectura/layering-exceptions.txt}.
\end{enumerate}

    CSV exfil-dns).
\end{itemize}

\section{Política de cambios al capítulo}

Cada vez que un \emph{flag} pasa de \code{experimental} a
\code{stable} (o entra una nueva categoría \code{future}), se
actualiza esta tabla \textbf{en el mismo PR} que modifica el
\emph{Cargo.toml}. Si la tabla y el código divergen, el código gana
---pero la divergencia cuenta como bug de documentación y bloquea
el merge.
