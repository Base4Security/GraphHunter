\section{Ciclos arquitectónicos}

\textbf{Cero ciclos} en \code{cargo metadata}. Se verifica con:

\begin{lstlisting}[basicstyle=\ttfamily\small]
cargo metadata --format-version 1 --no-deps | \
  jq '[.packages[] | {name, deps: [.dependencies[].name]}]' | \
  # construir DAG
  # detectar SCCs (Tarjan)
\end{lstlisting}

El CI ejecuta esta verificación en cada push a main.

\section{Benchmarks definidos}

\begin{itemize}
    \item \filepath{core/graph-engine/benches/hunt_latency.rs}:
    latencia de \code{run_hunt} sobre grafos de tamaño creciente.
    \item \filepath{core/graph-engine/benches/dedup_throughput.rs}:
    throughput del interner bajo carga concurrente.
\end{itemize}

Los resultados concretos no se fijan en este documento — varían
con hardware. CI compara contra baseline histórica y bloquea
regresiones $>$ 15\%.

\section{Cambios respecto al pre-rediseño}

Para contextualizar la evolución:

\begin{itemize}
    \item \textbf{Ciclos}: 1 (API $\to$ CLI $\to$ core) $\to$ 0.
    \item \textbf{Aristas indebidas}: 4 $\to$ 2.
    \item \textbf{Crates}: 4 $\to$ 14 (la separación hizo explícitas
    fronteras que estaban implícitas).
    \item \textbf{LOC en el core}: no se comparan 1:1 porque el
    core antiguo agregaba piezas que ahora viven en plataforma; la
    comparación útil es ``tamaño del algoritmo puro tras la
    limpieza'' contra ``tamaño del core de plataforma mezclada''.
\end{itemize}
